# PART 4 - UX DESIGN BIBLE
# Version 4.0 - Approved Visual System

DESIGN INTENT
Create a premium enterprise personal brand interface that is clean, dark, and trustworthy.
No generic portfolio look.

COLOR TOKENS (CANONICAL)
Use this palette exactly as baseline:
- --bg-primary: #02050a
- --bg-surface: #070b12
- --bg-surface-2: #03060b
- --line: #121826
- --accent-amber: #F5A623
- --accent-cyan: #46C2CB
- --success: #3DDC84
- --text-primary: #E7EAF0
- --text-muted: #7C8699

ACCENT USAGE RULES
- Amber: primary emphasis, key CTAs, highlight states
- Cyan: secondary actions, info labels, technical accents
- Success green: status only (active/completed indicators)

LAYOUT RULES
- Preserve scene-based storytelling layout
- Maintain fixed top nav and side progress rail behavior
- Keep content scannable for HR and detailed enough for engineers

CARD RULES
- Surface cards must be visually distinct from background
- Use consistent border radius and border treatment
- Hover border transitions can use amber or cyan based on context

TYPOGRAPHY RULES
- Display: Space Grotesk
- Body: Inter
- Mono: JetBrains Mono
- Maintain generous spacing and readability

PHOTO RULES (CURRENT APPROVED STATE)
For Who Am I and About Me portraits:
- No decorative frame borders
- No ring overlays
- Use image-only presentation with rounded corners
- Keep current visual height impression
- Slightly reduced horizontal width

BUTTON RULES
- Primary: amber background with dark readable text
- Secondary: ghost style with cyan hover emphasis

HERO CLEANLINESS RULE
Name block must blend into background with no hover highlight panel.

LINKEDIN ICON RULE
Footer social icon must always be visible and reliable.
Prefer local icon asset over fragile external icon URLs.

RESPONSIVE RULES
- Desktop, tablet, mobile must preserve hierarchy
- No text clipping, overlap, or horizontal overflow
- Chip rows should wrap naturally and remain readable

ACCESSIBILITY RULES
- Semantic structure
- Visible focus states
- Sufficient color contrast
- Meaningful alt text
